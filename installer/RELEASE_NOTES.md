## 1.18.0

**프록시 없이 원본으로 바로 시작**
- 컷을 열면 프록시 생성을 기다리지 않고 원본에서 바로 첫 화면이 나옵니다. 탐색·재생·분석·관절 재계산·보정 미리보기·렌더가 모두 원본에서 읽은 프레임으로 동작합니다.
- 원본에서 읽는 프레임은 예전 프록시와 같은 크기·같은 색 변환·같은 프레임 번호입니다(테스트에서 픽셀 단위로 동일). 분석 결과와 모델 입력은 바뀌지 않습니다.
- 읽은 프레임은 메모리에만 두고 용량 상한(기본 1.5GB, 모든 컷 합계)을 넘으면 오래된 것부터 버립니다. 디스크에 무압축 사본을 만들지 않습니다.
- 이미 분석한 컷은 분석했을 때의 크기를 그대로 씁니다(프록시를 지웠거나 해상도 설정을 바꿔도 매트·좌표 유지).
- 설정 > 프록시 만들기: 자동(원본 읽기가 재생보다 느리거나, 한 컷에서 이리저리 탐색할 때 백그라운드로. 원본에서의 탐색은 한 번에 약 0.2초, 프록시는 약 2ms) / 항상(백그라운드) / 만들지 않음. 프록시가 완성되면 열려 있는 컷도 그때부터 프록시를 읽습니다.
- 기존 프록시와 편집 타임라인의 공유 프록시는 그대로 씁니다. 일괄 분석과 타임라인 불러오기도 프록시를 먼저 만들지 않습니다.
- 원본이 없으면 그 사실을 표시합니다. 예전 프록시가 남아 있으면 볼 수는 있지만, 분석·렌더는 원본이 필요하다고 안내합니다. 타임라인 출력에서 프록시가 없다는 이유로 리터칭 컷을 원본으로 대신 넣던 동작을 없앴습니다.

**피부 보정 (2611 024컷)**
- 볼터치처럼 넓게 퍼진 볼 색이 '강하게'에서 지워지던 문제: 붉은기 보정이 얼굴 전체 대신 주변 피부를 기준으로 작은 붉은 반점만 고르게 합니다.
- 하이라이트(광)가 어두워지고 피부색으로 바뀌던 문제: 기본 보정(약하게·표준·강하게)이 광택 줄이기를 쓰지 않고, 광택 줄이기 슬라이더도 하이라이트의 색은 그대로 둡니다.
- 팔자주름·입가주름: 얇은 골뿐 아니라 얼굴 폭 10% 안팎의 넓고 부드러운 주름 그늘도 채웁니다(입술·콧구멍 주변 제외). '강하게'의 제거 값 60 → 80.
- 목주름: 목을 가로지르는 넓은 주름 그늘도 채웁니다(턱선 그림자는 유지). '강하게'의 목주름 50 → 70.
- 예전 버전에서 기본 보정을 적용한 인물은 값을 손대지 않았다면 프로젝트를 열 때 새 값으로 바뀝니다. 직접 바꾼 값은 그대로입니다.

## DIAP 1.16.1

**작업 보호**
- 저장에 실패하면 프로젝트 관리의 이름 변경·삭제, 일괄 분석, 렌더 시작, 타임라인 불러오기, 버전 전환, 새 프로젝트도 멈춥니다(1.16.0은 컷 전환·닫기·종료만 막았습니다). 렌더는 디스크의 프로젝트를 읽으므로, 저장하지 못하면 화면과 다른 상태로 렌더하지 않습니다.
- 관절 다시 계산이 30초 안에 끝나지 않으면 저장하지 않고 알립니다(계산 중인 추적을 덮어쓰지 않음).
- 같은 컷을 다시 열거나 프록시를 다시 만든 직전에 계산되던 화면이 다시 나오지 않습니다.

**출력**
- full range 영상(일부 카메라·휴대폰 영상)을 렌더하면 어둡고 밋밋해지던 문제를 고쳤습니다. 픽셀은 그대로 둔 채 limited range로만 표시했었습니다. 이제 limited range로 변환해 씁니다.
- 끝까지 만들어지지 않은 프록시(취소, 실패, 1.15 이전에 짧게 디코딩된 것)는 렌더·내보내기·분석에 쓰지 않고 다시 만듭니다.

**GPU**
- onnxruntime이 GPU를 쓰지 못하고 조용히 CPU로 실행한 모델도 알리고, 상태 표시에 "(일부 CPU)"가 붙습니다.

**기록**
- 분석할 때 쓴 모델 파일의 지문을 컷에 기록합니다(나중에 모델이 바뀌었는지 구분).

## DIAP 1.16.0

**작업 보호**
- 저장에 실패하면 컷 전환·프로젝트 닫기·종료가 멈춥니다(전에는 저장 안 된 변경이 그대로 사라졌습니다). 닫기와 종료는 "버리고 진행할까요?"를 묻고 기본은 "아니요"입니다.
- 관절을 고친 뒤 바로 다른 컷으로 가도, 다시 계산은 고친 컷에 적용되고 저장됩니다(전에는 새로 연 컷의 추적에 잘못 적용될 수 있었습니다).
- 컷을 바꾸는 순간 계산 중이던 이전 컷의 프레임이 새 컷 화면에 나오던 문제를 고쳤습니다.
- 마지막 컷 끝에서 재생이 멈춥니다(구간 반복 끔). 23.976fps가 2% 빠르게 재생되던 문제를 고쳤습니다. 컷을 오가도 컷마다 실행 취소 기록이 남습니다.

**렌더 정확도**
- 렌더가 미리보기와 같은 결과를 냅니다. 렌더가 limited range(일반 ProRes) 영상을 full range처럼 읽어 피부 밝기 등이 미리보기보다 세게 들어갔습니다(회색 51 + 밝기 50%: 미리보기 86, 렌더 95 → 둘 다 86).
- 영상이 메타데이터보다 짧게 디코딩되면 렌더를 실패로 처리하고 짧은 파일을 남기지 않습니다. 프록시도 검은 꼬리로 완료 처리하지 않고 알립니다.

**색공간**
- 타임라인 컷 하나의 색공간을 바꾸면 모든 컷이 함께 쓰는 프록시가 그 색공간으로 다시 만들어져 다른 컷이 전부 잘못 보이던 문제를 고쳤습니다(1.15.0). 그 컷만 자기 프록시를 만듭니다.
- 분석한 컷을 log와 log가 아닌 색공간 사이에서 바꾸면 다시 분석할지 묻습니다.

**속도·저장 공간**
- 프록시를 프로젝트 폴더(NAS)가 아니라 이 PC의 캐시 폴더에 만듭니다(설정 > 캐시 폴더, 사용량·남은 공간 표시, 목록에 없는 프로젝트 캐시 지우기). 기존 프로젝트의 프록시는 그대로 쓰고, 프로젝트 관리에서 "프록시 캐시 정리"를 하면 이 PC에 새로 만듭니다.
- 프록시·매트를 만들기 전에 남은 공간을 확인합니다.

**GPU 메모리**
- GPU 메모리가 부족하면 메모리를 비우고 다시 시도하고, 그래도 안 되면 그 컷만 실패로 표시하며 이유를 알립니다. 모델이 GPU 대신 CPU로 돌게 되면 알립니다. 일괄 분석을 시작하면 미리보기가 쥔 GPU 메모리를 놓습니다.

**설치·모델**
- onnx가 기본 설치에 들어갑니다(SAM 3.1 인물 찾기에 필요. 학습 패키지 설치가 실패하면 빠져서 인물 찾기가 조용히 꺼졌습니다).
- 빈 파일·오류 페이지·중간에 끊긴 다운로드를 모델로 인정하지 않고, 열리지 않는 모델은 다시 받습니다.

**로그**
- 출력·오류·크래시·화면 멈춤(5초 이상, 모든 스레드 위치)을 로그 폴더에 남깁니다. 설정 > 로그 폴더 열기.

## DIAP 1.15.0

**재생**
- 재생 버튼 옆에 구간 반복 버튼이 생겼습니다. 켜면 지금 컷만 반복하고, 끄면 컷 끝에서 다음 컷으로 이어서 재생합니다(설정은 기억됩니다).
- 이어 재생은 끊기지 않습니다. 재생하는 동안 다음 컷을 미리 열고 앞부분을 미리 계산해 두었다가, 컷 끝에서 바로 넘어갑니다. 프록시가 없는 컷은 그동안 프록시를 만듭니다.
- 재생 중에 재생 버튼이 좌우로 밀리던 문제를 고쳤습니다(가운데 고정).
- 호버 상태로 재생하면 멈추던 문제를 고쳤습니다(재생 중에는 호버 표시를 끕니다).
- 피부 보정 영역 표시를 켜고 재생하면 매우 느리던 문제를 고쳤습니다(영역 계산을 백그라운드로 옮김).

**피부 보정**
- 보정 강도나 입가주름·팔자주름·여드름을 눌러도 화면이 멈추지 않습니다. 계산하는 동안 미리보기 오른쪽 아래에 회전 표시와 "보정 계산 중"이 나옵니다.
- 원본 그레인이 남습니다. 피부결 보정이 지운 가장 미세한 성분(그레인)을 원본에서 되돌려 넣습니다.
- 강하게에서 피부색이 창백·차갑게 바뀌던 문제를 고쳤습니다. 홍조 보정이 붉은 부분만 고르게 하고 얼굴의 평균 색은 그대로 둡니다.
- 강하게에서 눈 안쪽(콧대 옆)이 하얗게 들뜨던 문제를 고쳤습니다. 다크서클 보정이 눈 안쪽 끝으로 갈수록 약해지고, 다크서클 자체의 깊이만큼만, 정해진 양 이하로 밝힙니다.

**컷 목록**
- 여러 컷을 선택하면 파란 테두리와 체크 표시가 붙고, 위에 "N컷 선택"이 나옵니다(타임라인도 같음).
- 열린 컷이 컷 목록 가운데에 오도록 스크롤됩니다.
- 각 컷의 입력 색공간이 상태 줄 오른쪽에 작게 표시됩니다.

**색공간**
- 컷을 추가할 때 파일 이름과 카메라 태그로 색공간을 자동 판정합니다(S-Log3, LogC3, LogC4). 근거가 없으면 Rec.709로 둡니다.
- 출력 탭의 입력 색공간에서 직접 바꿀 수 있고, 컷 목록에서 여러 컷을 선택한 채 바꾸면 모두에 적용됩니다. "변환 없음"은 "Rec.709 (변환 없음)"으로 이름을 바꿨습니다.
