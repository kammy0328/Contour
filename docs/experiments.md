# 모델 실험 제안 (기본 구성 변경 전 비교 필요)

기본 모델 구성은 바꾸지 않는다. 아래 실험은 실제 영상에서 같은 기준으로 비교한 뒤, 모든 항목이 기존과 같거나 나을 때만 기본값으로 올린다.

## 공통 비교 기준

- 영상: 2611_1MxKPDH_PV, lngshot_wanna_go_v3, ILLIT_1013의 분석 컷(군무·겹침·화면 이탈·재등장·모션 블러·색 조명·log 포함)
- 정답: 사람이 확인한 관절(benchmark.py에 등록한 컷)과, 사람이 고친 인물 연결. 자동 결과를 정답으로 쓰지 않는다. 학습·검증은 영상 단위로 나눈다.
- 측정:
  - 관절 오차(전체, 가림 구간, 블러 구간)
  - 인물 번호 혼동(ID 전환 횟수)
  - 마스크 IoU와 프레임 간 흔들림(같은 사람 마스크의 경계 변화)
  - 얼굴 인식 비율과 피부 보정 벤치마크(skinbench.py) 지표
  - 컷당 처리 시간, 단계별 시간, VRAM 최대치
- 실행: PC(RTX 4070 Ti 12GB)에서 사용자 프로젝트를 복사한 별도 프로젝트로. 결과는 jobs/out에 JSON으로.

## 지금까지 측정된 사실 (2026-11-17, j2680~j2682)

- 분석 시간의 80~90%는 SAM 3.1 인물 분할(인코더)이다. 포즈 모델은 호출당 5~50ms.
- SAM 3.1 인코더는 단독 0.41초/회. GPU 메모리가 11.7GB/12GB 근처로 차면 2~37초/회로 느려진다(드라이버의 시스템 메모리 대체로 보임).
- FP16 인코더(onnxruntime float16 변환)의 마스크는 FP32와 IoU 0.998 이상.
- TensorRT는 이 PC에 nvinfer가 없어 쓸 수 없다.

## 실험 1: 선택적 포즈 앙상블

- 기본: RTMW-x 하나. RTMW의 관절 신뢰도가 낮거나, 모델 간 불일치(disagree)·가림·블러·낮은 추적 신뢰도 구간에서만 RTMPose-x, DWPose-L, 좌우 반전 TTA를 추가.
- 기대 효과: 포즈 단계 시간 감소. 다만 포즈 단계가 전체의 10% 안팎이라 전체 시간 이득은 작다(측정상).
- 위험: 쉬운 프레임으로 판정했다 틀리면 관절이 튐. 가림·회전 구간의 관절 오차와 ID 전환을 반드시 비교.

## 실험 2: SAM 3.1 기준 프레임 + SAM 2 비디오 전파

- 방식: SAM 3.1을 기준 프레임(컷 시작, 인물 등장, N프레임마다, 추적 신뢰도가 떨어질 때)에만 돌리고, 사이는 SAM 2.1 비디오 추적으로 마스크를 전파. 주기적으로 SAM 3.1로 다시 고정.
- 기대 효과: 인코더 호출 수 감소로 분석 시간 큰 폭 감소, VRAM 압박 완화.
- 위험: 겹침·교차·화면 이탈 후 재등장에서 마스크가 다른 사람으로 넘어가거나 사라짐. 마스크 IoU, 흔들림, ID 전환을 기존(매 프레임 SAM 3.1)과 비교. 기준 프레임 간격별(4, 8, 16)로 측정.

## 실험 3: 메모리 압박 줄이기 (모델 교체 없이)

- 세션 옵션: CUDA 메모리 풀 요청량만큼 확장(kSameAsRequested), 유휴 스레드 spin 끄기, 스레드 수.
- SAM 3.1 인코더 FP16.
- 분할 단계 동안 쓰지 않는 세션 내리기.
- 측정: 컷당 시간, VRAM 최대치, 마스크 IoU(기존과 0.995 이상이어야 함). j2682가 이 비교를 하던 중 중단됨.

## 후속 실험 (1.18 원본 우선 구조 이후, 기본값 변경 전 비교 필요)

- 압축 프록시: 지금 프록시는 무압축 8bit RGB. 압축(예: 인트라 코덱)으로 바꿀지는 읽기 속도, 용량, 분석 입력 오차(프록시 픽셀 대비 최대·평균 차이, 관절·매트 차이)를 같은 컷에서 비교한 뒤 결정한다. 근거 없이 특정 코덱을 기본값으로 두지 않는다.
- 작은 얼굴·손을 원본 해상도 crop으로 분석: 입력 분포가 바뀌므로 구조 변경과 분리해 정확도·ID 혼동·마스크 흔들림·속도·VRAM을 비교한다.
- 긴 컷(메모리 풀보다 큰 컷)에서 분석 패스마다 원본을 다시 디코딩하는 비용: 자동 모드에서 분석 시작 전에 프록시를 만들지, 풀 크기를 컷 길이에 맞출지 PC 측정으로 결정한다.

## 실험 4: 피부 결함 전용 검출 모델 (1.19의 규칙 기반 검출로 부족할 때)

1.19는 규칙 기반 다중 크기 검출(retouch/detect.py)이다. 아래는 그 한계가 실제 작업 영상에서 확인될 때만 진행하는 별도 실험이며, 검증 전에는 기본 검출을 교체하지 않는다.

- 모델 후보: 작은 U-Net 또는 SegFormer-B0 계열(입력: 얼굴·목 crop의 표시 색 RGB + 피부·목 마스크, 출력: dark/red/bump/line/fold/protect 6채널 점수 지도). ONNX로 내보내 기존 추론 경로(models.py)를 쓴다.
- 정답 데이터: 자동 검출 결과를 정답으로 쓰지 않는다.
  - 수작업 리터칭 전후 쌍(TEST003/004 AFTER, 2611 069 스틸)의 차이에서 리터처가 실제로 지운 위치를 뽑고 사람이 종류를 확인한다.
  - DIAP의 검출 영역 보기에서 사용자가 누락·오검출을 표시한 것(추가 기능이 필요하므로 별도 제안).
  - 합성 결함(실제 피부 crop에 위치·크기·세기를 알고 넣은 것)은 사전 학습과 회귀 측정용으로만 쓰고, 최종 평가는 실제 결함으로 한다.
- 분리: 학습·검증은 영상(컷) 단위로 나눈다. 같은 컷의 인접 프레임이 양쪽에 들어가지 않게 한다. 프로젝트 단위 분리를 기본으로 한다.
- 비교 기준(규칙 기반 대비): 종류별 누락·오검출, 보호 영역(털·장신구·옷깃·그림자) 손상, 그레인 유지, 프레임 간 흔들림, 처리 시간, VRAM. 정면·옆모습·고개 숙임·회전·손 가림·색 조명·log·블러·작은 얼굴·클로즈업을 각각 본다.
- 이미 측정된 사실(2026-11-17, j2720과 합성 삽입 평가): 릴리스 노트 1.19와 완료 보고 참조. 규칙 기반이 약한 곳: 초점이 나간 얼굴의 약한 결함, 진한 그레인 속 3px 이하 결함, 접힘과 구분이 어려운 긴 그림자.

## 실험 7: DIAP 통합 모델 (얼굴 파싱 + 의상 + 인물 알파, 기본 꺼짐)
- 목적: face_parse(SegFormer-B5), parse_clothes(SegFormer-B2), matte_rvm(RVM) 세 모델을 DIAP 모델 하나로. 교사 세 개의 답으로 학습한 학생(ResNet-34 공용 인코더 + 얼굴 19 / 의상 18 / 알파 헤드), ONNX 한 파일(unified_diap.onnx, 입력 크기 32의 배수 자유).
- 코드: contour/learn/unified (teach 교사 라벨, net, train 부분 라벨 손실·프로젝트 단위 분리, bench 비교), 앱 쪽 contour/track/unified.py (settings.unified_model 또는 DIAP_UNIFIED=1일 때만, 실패하면 그 기능만 원래 모델로).
- 라벨: 앱이 각 교사에 넣는 그대로(얼굴 크롭 원본, 인물 박스 크롭과 프레임은 analysis_view). RVM 알파는 인물 합집합이라 "사람이 여기 있고 이만큼 부드럽다"만 배우고, 픽셀의 주인은 지금처럼 추적 라벨.
- 비교 기준: 교사의 원본 화면 답. 행: 교사의 어려운 화면 답 / 통합 모델 원본 / 통합 모델 어려운 화면. 얼굴 피부·목 IoU, 눈·입·머리 경계 F1, 누수, 깜빡임 / 의상 IoU·치마·원피스·피부 위 의상 / 알파 MAD·경계·기울기·깜빡임 / 모델·실행 공급자별 시간과 GPU 메모리.
- 라이선스: 비상업 교사의 답으로 배운 학생도 교사 조건을 그대로 따른다고 보는 게 안전(사내 사용).
- 아직 사람이 표시한 가림·보호 라벨이 없어 "가려진 얼굴에서 새는 픽셀"은 교사 기준 누수로 대신함. 수작업 표본이 생기면 bench에 추가.
- 활성화: 세 기능 모두 교사 대비 나빠지지 않을 때만 별도 변경으로. 그때 예전 마스크 다시 계산(unified.stale) 연결과 배포 빌드 확인.

## 실험 8: 원본만으로 포즈 자가학습 강화 (refiner)
- 라벨 auto_track_v2: teacher_mask에서 인물 겹침(가림·번호 바뀜 위험) ±4프레임, 앞뒤 추적 충돌 구간 ±4프레임, 빠른 관절(인물 크기의 15%/프레임 이상), 플래시 프레임 제외. 쉬운 선명 프레임을 표본의 1/4로 넣고 학습 때 항상 어렵게(노출·색 조명·블러·JPEG). 회전·크기 증강은 정답 좌표도 함께 변환.
- 검증: 프로젝트가 3개 이상이면 프로젝트 단위로 분리(같은 뮤직비디오가 학습·검증에 섞이지 않게), 기록에 grouping.
